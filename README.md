## Quick Start

New here? `install_packages.sh` installs OS packages in three modes: straight from the internet
(`online`), or by pre-downloading them on a connected host (`save`) so you can install them later on
an **air-gapped** machine (`offline`).

**Prerequisites**
- A supported OS: Ubuntu/Debian, RHEL/CentOS/Rocky/AlmaLinux/Fedora, or SLES/openSUSE Leap
- `root` / `sudo`
- Internet access for `online` and `save` (not needed for `offline`)

**1. Get the script**
```bash
git clone https://github.com/Chubtoad5/install-packages.git
cd install-packages
chmod +x install_packages.sh
```

**2. Pick a mode, then list the packages you want**
```bash
# Install now, from the internet:
sudo ./install_packages.sh online curl jq git

# Download the packages into a tarball to carry to an air-gapped host:
sudo ./install_packages.sh save curl jq git

# On the air-gapped host (with the saved tarball in this folder), install with no internet:
sudo ./install_packages.sh offline curl jq git
```

> The offline host must run the **same OS version** as the host that created the tarball, or you'll
> hit dependency errors. The script does **not** add third-party repos or GPG keys (e.g. `docker-ce`,
> `kubectl`) — set those up first. See [Usage](#usage) below for the full parameter reference.

## Pre-requisites

- Supported operating systems: ```ubuntu|debian|rhel|centos|rocky|almalinux|fedora|sles|opensuse-leap```
- Internet connection when using 'online' and/or 'save'
- When using 'offline' a pre-generated tarball from 'save' must be copied to the same directory the script is running
- When using 'offline' the air-gapped host operating system must be the same version and kernel as the host that generated the tarball to avoid package dependency errors

## Limitations

- install_packages.sh does not automatically add repositories or GPG keys. Packages that require special repository handling, such as docker-ce, or kubectl must be added prior to running this script.

## Behavior Notes

- `save online` saves the tarball **before** installing, so the archive always captures the packages and their dependencies even when some are already installed on the build host.
- On RHEL-family hosts, `save` downloads the **full dependency closure** (`dnf download --resolve --alldeps`), including packages already installed on the build host. Archives are larger, but offline installs on minimal images no longer fail on missing dependencies.
- On SLES/openSUSE hosts all zypper operations run non-interactively, and `save` uses a private package cache — the host's `/var/cache/zypp/packages` is never touched.
- **SUSE `save` limitation:** zypper has no `--alldeps` equivalent, so dependencies that are *already installed* on the build host are not bundled. For guaranteed air-gap closure, build SUSE save archives on a minimal/fresh host (the script prints this reminder on every SUSE `save`).
- In `offline` mode the original package manager configuration (apt sources, dnf repo file, zypper repo list) is **always restored**, even when the install fails or is interrupted. The script only ever adds a temporary local repository scoped to the install — it never removes or replaces the host's configured repositories.
- `offline` mode validates that the tarball contains packages for the running OS family before installing, and fails early with a clear message if it does not.
- The `offline-packages/` directory in the working directory is the script's staging area: stale copies are removed (with a message) at the start of `save` and `offline` runs, and the extracted staging directory is cleaned up when the script exits.
- The tarball is written atomically — an interrupted `save` never leaves a truncated `offline-packages.tar.gz` behind.
- `-h`/`--help` exits 0. Unknown `-flags` are rejected with an error instead of being treated as package names.

## Usage

```
git clone https://github.com/Chubtoad5/install-packages.git
cd install-packages
chmod +x install_packages.sh
sudo ./install_packages.sh
```

```
Usage: install_packages.sh [offline] [save] [online] [package1 package2 package3 ...]

This script must be run with root privileges.
At least one parameter is required followed by a list of packages to install. [save] and [online] may be used together followed by the package(s) list. [offline] must be used alone followed by the package(s) list.

Parameters:
  offline         : Installs packages from an offline tarball that was generated by this script.
                    Tarball must be placed in the same directory as this script. Offline host must be running the same OS type and version.
  save            : Downloads and saves packages and dependencies as an offline install tarball.
  online          : Install packages and dependencies from the internet using default package manager repositories.
  [package(s)...] : A space separated list of package names to process.

Options:
  -h, --help      : Show this help and exit.

Example:
  Only install the packages:
  sudo ./install_packages.sh online python3 python3-pip

  Only save the packages:
  sudo ./install_packages.sh save python3 python3-pip

  Save and install the packages:
  sudo ./install_packages.sh save online python3 python3-pip

  Install packages from an offline tarball:
  sudo ./install_packages.sh offline python3 python3-pip
```

## Version pinning

Pinning is optional. With no pin, and no new flag, everything works as it always has.

```bash
# Any supported distro. The start of a version is enough: this takes the newest 28.5.2 build.
sudo ./install_packages.sh online docker-ce=28.5.2 docker-ce-cli=28.5.2

# Leave what's already installed alone, and still install what's missing
sudo ./install_packages.sh online --no-upgrade docker-ce jq

# A pin older than the installed version refuses, unless you ask for it
sudo ./install_packages.sh online --allow-downgrade docker-ce=28.5.2

sudo ./install_packages.sh --version
```

- A version that doesn't exist stops the run before anything is installed, and lists what's available.
- `28.5` matches `28.5.2` but not `28.50`. An exact version wins over a longer build with the same start.
- `save` downloads the pinned version and records it in `offline-packages/pins.lock`. `offline` only looks in the bundle.
- `--no-upgrade` covers the packages you name, not every dependency.
- Holding a package against later upgrades (`apt-mark hold` and the like) is out of scope.
- A pin needs `dnf` on the RHEL family. The older `yum` fallback fails with a clear message.
